Model Context Protocol

Ask your own agent

This portfolio is also a remote MCP server. Add one line to your client and your Claude — not a chat widget on someone else's website — can read the projects, the case studies, the CV and the design-system statistics directly.

It is read-only, unauthenticated and stateless. Six tools, no writes, no sign-up, no key. The interesting part is not that an MCP server exists; it is that these six tools are the same functions the site's own assistant calls in process, so a bug cannot exist on one surface and not the other.

01

Install

Streamable HTTP · no authentication
Endpoint https://yordan-portfolio.vercel.app/api/mcp
Read-only No auth Stateless 6 tools

Claude Code — one command

The fastest route. Run it in any project; add --scope user to make it available everywhere.

claude mcp add --transport http yordan https://yordan-portfolio.vercel.app/api/mcp

Then ask, in Claude Code: “What did Yordan do at Domestina?” It will call get_project and answer from the returned text.

Claude Desktop — config file

Settings → Developer → Edit Config opens claude_desktop_config.json. On macOS it lives at ~/Library/Application Support/Claude/; on Windows at %APPDATA%\Claude\. Paste the block below — if the file already has an mcpServers object, add the "yordan" entry inside it rather than creating a second one — then quit and reopen Claude Desktop. 

{
  "mcpServers": {
    "yordan": {
      "url": "https://yordan-portfolio.vercel.app/api/mcp"
    }
  }
}

The tools then appear under the tools icon in the composer. Nothing needs to be installed locally: the server runs as a function on this site, not on your machine.

Anything else

Any client that speaks MCP streamable HTTP works — point it at the endpoint and POST JSON-RPC. There is no GET stream and no session id, because the server keeps no state between requests; every call is complete in one round trip. To look under the hood without a client at all: 

curl -s https://yordan-portfolio.vercel.app/api/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
02

The tools

Six, deliberately — every one read-only
list_projects
The catalogue — every project as a compact record: id, title, client, period, tags and a one-line summary. Optional filters for tag, client and whether a full case study exists. Start here if you do not know what the corpus contains.
get_project
One project in full: summary, subtitle, every body section in the order it was written, metrics, links, media slots and tags. Sections are an ordered array, and a section kind may appear more than once.
list_experience
Employment history, most recent first — organisation, role, dates, location, working mode, a one-line descriptor and the bullet points for each role.
get_profile
The person: identity, location, availability, contact details, the skills taxonomy, education, languages and three personal facts. These are structured fields, so this is the only tool that can answer “where is he based?” or “is he available?”.
get_system_facts
The repository rather than the work: the design system's own token and component counts, corpus statistics, and the case study about how this site is built. Asked more often than you would expect.
search_content
Lexical BM25 across every chunk of the corpus, returning ranked passages with their citations. It is keyword search, not semantic — and an empty result means the corpus does not cover the question, which is the answer rather than a failure.

Every tool declares readOnlyHint · destructiveHint false · openWorldHint false — the protocol's own way of saying nothing here can change anything

03

Why MCP

And where it deliberately is not used

MCP here is a distribution surface, not this app's internal boundary. That distinction is worth stating plainly, because putting an agent↔tool protocol behind a public web chat invites a fair question: is the protocol doing real work, or is it architecture worn as a costume?

The tools are the asset; the protocol is one way to reach them. They live in lib/knowledge/ as pure functions over a generated content index — no network, no state, no dependencies. The site's own assistant imports that module and calls it in process. This endpoint imports the same module and exposes the same six functions to anyone. Two consumers, one core.

The web chat does not call this endpoint, and that is deliberate. Routing it through here would mean the serverless function calling itself over HTTP once per tool call — an extra hundred to three hundred milliseconds per hop, a second cold-start path, and a self-referential dependency, all bought to satisfy a purity argument. The Claude API supports remote MCP servers natively, so this was a real option rather than a straw man. It was rejected on latency and on the self-call.

What the endpoint adds is the thing a reader can take away. A chat widget only works while you are on the page. An MCP server installs into your tooling and answers from wherever you already work — inside a review, next to a job spec, in a terminal. That is the whole feature, and it costs a page and a JSON snippet.

Both surfaces share the core, so a tool bug cannot exist in one and not the other. That equivalence is the argument for the boundary being where it is — and it is also why the retrieval underneath got measured and published rather than asserted.

04

Limits

What it will not do, stated up front

Read-only by construction

No tool writes, mutates or sends anything. There is nothing to authorise, so the worst case of an abused endpoint is cost, never data.

Stateless

No session, no memory, no per-caller history. Each request is complete on its own and nothing about you is stored.

A closed corpus

One person's work, written by him. Ask it something outside that and it returns nothing — which is the correct answer, not a bug.

No model, no key

The server spends no inference. Your own client pays for the reasoning; this endpoint only hands it text.

Rate limited

Throttled per address at the edge, before the function runs. Fair use is generous; scraping is not the intended shape.

Content, not a contract

The corpus changes when the work does. Tool names and shapes are stable; the words inside them are meant to move.
